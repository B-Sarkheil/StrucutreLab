# Structure Lab

Integrated engineering desktop software for Windows (Python + PySide6) for about 30 users. It gradually replaces scattered MATLAB and Excel-VBA tools. Each tool is a plugin.

First real tool: **Auto Design**, automatic structural section optimization (Genetic Algorithm + SAP2000 OAPI). It is currently **hidden from users** (shown as "Planned", see `AUTO_DESIGN_ENABLED` in `plugins/registry.py`) while development is paused. Second tool: **SLD to SAP**, loading the SAP2000 model from piping SLD files exported from AutoCAD (the only tool users can open today).

Design context lives in these docs in the project knowledge:

* `claude/engineering-platform-decisions.md`: bootstrap / runtime / app layers, auto-update from the server, IT constraints.
* `docs/contract.md`: the frozen contract between the launcher and the app (layout on the user machine, server share, update rules).
* `claude/project-plan-structural-optimization.md`: Auto Design plan (Phase 1 GA, Phase 2 ML surrogate lab, Phase 3 general model).
* `docs/sld_to_sap_algorithm.md`: the SLD to SAP algorithm guide. The code is the reference; if they disagree, the guide must be fixed (or, after a decision, the code).

The user's tested MATLAB program that drives SAP2000 (`connectToSAP.m`, `openSapModel.m`, `modelingOneLine.m`, `designOneLine.m`, `getDesignResultsType1.m`, `modifyProfilesType1.m`, `modifySapModelType1.m`) is also in the project knowledge. It is the reference for SAP2000 API calls; the user can extract the exact method signatures from the DLL in MATLAB on request. The MATLAB reference of SLD to SAP is `SLD2SAP.m` (v1.4) with `SLD2SAP.lsp`.

## How the app works

* `__main__.main()`: `setup_logging()` → QApplication → `apply_theme` → `register_builtin_plugins()` → `MainWindow` → `app.exec()`.
* **Plugin contract** (`plugins/base.py`): `name` (unique key), `title`, `icon`, `description`, `available` (False = planned, not built), and `create_widget() -> QWidget`.
* **Registry** (`plugins/registry.py`): explicit and simple. `register_builtin_plugins()` lists all plugins in navigation order (Auto Design, SLD to SAP, PDMS to SAP, Auto CPS); `load_plugins()` returns them. No auto-discovery yet. **Release switch:** `AUTO_DESIGN_ENABLED` (currently `False`): while False, Auto Design is registered as a `PlaceholderPlugin` with the same name, title, icon and description, so it appears in the sidebar and on Home as a planned tool and opens the "Under development" page. The real `AutoDesignPlugin` and all its code stay in the project; set the switch to `True` to bring it back.
* **Shell** (`ui/`): `MainWindow` reads the registry and passes the plugins to `Navigation` (sidebar) and `HomePage`. Clicking a sidebar item or a card calls `MainWindow.show_page(key)`. Home is built at startup; each plugin page is created lazily on first open and kept in a `FadeStackedWidget` (a `QStackedWidget` that fades the new page in). If `create_widget()` fails, the error is logged and the current page stays. The About page is a shell page (not a plugin) opened from the About card at the bottom of the sidebar.
* **Home page caveat:** `home_page.py` has a fixed list `plugin_order = ["auto_design", "sld_to_sap", "pdms_to_sap", "auto_cps"]`; only plugins named there get a card or row. A new plugin must be added to that list until it is replaced by the registry order (see known issues).
* **Not implemented yet (shown as planned, open the "Under development" page):** Auto Design (hidden by the release switch), Auto CPS and PDMS to SAP.
* **Visual language** ("structural drawing sheet"): all colors are tokens at the top of `ui/theme.py` (blueprint-ink surfaces, drafting-cyan linework, amber as the single signal color for active/hover/focus). Titles use Bahnschrift, body uses Segoe UI. Most widgets are styled by `objectName` in the stylesheet; cards, the hero banner and the sidebar marker are painted in code (`ui/widgets.py`, `ui/home_page.py`, `ui/navigation.py`) and read the same tokens. Available tools get large cards, planned tools get dashed rows. The hero banner fades its logo in once over 5 s (`HeroBanner.FADE_MS`), which is the only unprompted motion in the app; the About page logo emblem spins while visible. `ui/loading_overlay.py` is the shared loading overlay (delay 200 ms, minimum visible 450 ms, blocks input to the page below).

## Release and update system (done, first release 1.1.5 installed and started on the user's PC)

Three layers (details and frozen rules in `docs/contract.md`). Installed copy: `%LocalAppData%\Structure Lab\` (with a space; `core/paths.py` has `APP_NAME = "Structure Lab"` and uses `STRUCTURELAB_ROOT` when the launcher sets it).

* **Installer** (`bootstrap/installer.iss`, Inno Setup 6 or 7): per-user, no admin rights, silent mode `/VERYSILENT`, no entry in Programs and Features (`Uninstallable=no`). Copies bootstrap (small Python + `launcher.py` + `initial.json`), the first runtime and the first app version, plus `settings.json` (server path; never overwritten by a re-install). Start Menu shortcut (and optional desktop) runs `bootstrap\python\pythonw.exe bootstrap\launcher.py`, with `AppUserModelID` `StructureLab.App` and the icon `app.ico`. The Setup.exe is given to users once; it is **not** part of the server folder.
* **Launcher** (`bootstrap/launcher.py`, standard library only): on every start reads `latest.json` from the server share with a 5 s timeout (unreachable server: skip, start the installed version). If the server app version is higher: downloads the needed zips to `tmp\`, checks sha256, extracts beside the target, renames atomically, runs the self-check (`ping_app()` with the new runtime and the new app), then switches `state.json`. A failed self-check deletes the new folders and records the version in `rejected`. Keeps only the current and the previous app/runtime. A lock file prevents two instances updating at once. The app runs as a child process with the runtime's `pythonw.exe`; if it exits within 6 s a message box is shown. The update never restarts a running app: the new version starts at the next launch.
* **Logs** are local only: `%LocalAppData%\Structure Lab\logs\` (`launcher.log` for updates, `app.log` for the app, `app_stderr.log` for startup errors). `core/logging_setup.append_server_log` is an unused stub; `core/config.Settings` only has `server_dir` and `channel` (the contract's `network_timeout_sec` is read by the launcher, not by the app).
* **Server share:** `\\be-sarkheil\Share\Structure Lab` (read access for users). Holds `latest.json`, `app-<version>.zip`, `runtime-<id>.zip`. Old zips stay there (publish.py never deletes); only the ones in `latest.json` are needed.
* **`tools/build.py`:** reads the version from `src/version.py` (stops if `pyproject.toml` shows another one), zips all files under `src/`, builds the runtime zip from `runtime/python` only when the runtime id changes (id = hash of `runtime/requirements.txt` + Python DLL name; dev packages, `Scripts/` and `__pycache__` are left out; the dev `python312._pth` with `..\..` is replaced by a clean one), writes `latest.json` last. With `--installer` it also builds `dist\stage` and `dist\StructureLab-Setup.exe` (ISCC is found in the usual Inno Setup 6/7 folders or with `--iscc`).
* **`tools/publish.py`:** copies the zips from `dist\publish` to the server (skips files that are already there), `latest.json` last.
* **`min_bootstrap_version`** in `release_config.json` is the version of the *launcher*, not of the app. Change it only when `launcher.py` changes and a new Setup is required (users are then told once to ask IT).

How to release a new version (e.g. 1.1.6), no new Setup needed:

1. Change the code and test. 2. Set the new version in `src/version.py` (and `pyproject.toml` unless it reads the version from `version.py`). 3. `.\runtime\python\python.exe tools\build.py` 4. `.\runtime\python\python.exe tools\publish.py`. Users get it at their next launch. A rejected version is not retried: publish a higher version to fix it. Going back means re-publishing the old code with a higher number.

First release / new Setup: `.\runtime\python\python.exe tools\build.py --installer [--iscc "<path>\ISCC.exe"]`, then `publish.py`, then hand `dist\StructureLab-Setup.exe` to the users. If you add a library, install it into `runtime\python` first (`pip install -r runtime\requirements.txt`); the runtime id changes and users download the new runtime once.

## Auto Design (current state; hidden from users, see the release switch)

A wizard inside the plugin; the shell knows nothing about its steps.

1. **Step 1 – settings form** (`ui/page.py`). Fields and the variable each is stored in: Population Size `popSize`, Tournament Size `tournamentSize`, Number of Generation `genSize` (positive integers); Mutation Percent (%) `mutationPercent` (0–100); Penalize Level Coefficient `penalizeLevel`; Tolerance to Detect Member as Beam or Column (cm) `tolerance` (positive decimals); SAP2000 Reference File `sapPath` (Browse, `.sdb`). Validation runs on Next with inline errors; extra rule: `tournamentSize <= popSize`. Next emits `AutoDesignParams`.
2. **Step 2 – allowed sections** (`ui/sections_page.py`). In a worker thread: connect to SAP2000 (attach to a running instance, else start one) → open `sapPath` → read frame section names (`PropFrame.GetNameList`). Table columns: Section, Is Allowed for Column, Is Allowed for Beam, Is Allowed for Horizontal Brace, Is Allowed for Vertical Brace (`SectionPermission` fields `allowedForColumn`, `allowedForBeam`, `allowedForHorizontalBrace`, `allowedForVerticalBrace`; the role list `ROLES` in `sections_page.py` and `HEADERS` in `sections_excel.py` must keep the same order). Each cell toggles No/Yes on click or Space/Enter; default No. Loading shows a progress bar; failure shows the message and a Retry button. Next requires at least one Yes and emits `list[SectionPermission]`. A Back button returns to step 1. Tools for editing long section lists (all of them work on the table data, never on SAP):
    * **Name filter** above the table. Plain text matches anywhere in the name; text with `*` / `?` must match the whole name (`IPE*` starts with IPE, `*300` ends with 300, `?` is one character); a comma or `;` separates several patterns (`HEA*, IPE*`). Case is ignored. The filter only hides rows.
    * **Apply to the shown sections**: choose a role (Column / Beam / Horizontal Brace / Vertical Brace) and press `Set Yes (N)` or `Set No (N)`; only the N rows that pass the filter change.
    * **Undo / Redo** (buttons, Ctrl+Z, Ctrl+Y / Ctrl+Shift+Z). Every click, every bulk action and every Excel import is one step. The history is cleared when the sections are reloaded from SAP. While the filter box has focus, Ctrl+Z undoes its text instead.
    * **Live counters** under the table: `Allowed: Column n | Beam n | Horizontal Brace n | Vertical Brace n` and `Showing x of y`. Counters, Export and Next always use all rows, shown or hidden. There is deliberately no warning when a role has zero sections, because a user may legitimately not use a role.
    * **Excel export / import** (`Export…` / `Import…` buttons, logic in `services/sections_excel.py`, needs `openpyxl`, imported lazily). Export writes one sheet with the header `Section`, `Is Allowed for Column`, `Is Allowed for Beam`, `Is Allowed for Horizontal Brace`, `Is Allowed for Vertical Brace` and a Yes/No drop-down in the cells. Import matches rows by section name (all five header names must exist, so an old three-role file is rejected with a message naming the missing columns; Yes/No also accepts y/n/true/false/1/0/x, an empty cell means No). If any cell has another value, nothing is applied and the first bad cells are reported. Sections in the file but not in the model are ignored, sections in the model but not in the file stay unchanged, and both counts are shown. Import ignores the filter and is one undo step.
3. **Wizard state** (`ui/wizard.py`): `params` (AutoDesignParams), `sections` (the list from step 2, the variable the user asked for), `sap` (the live `SapClient`). Going Back and Next again with the **same** `sapPath` reuses the loaded page (no reconnect, choices kept, undo history kept); a **different** `sapPath` rebuilds step 2 from scratch.
4. **Next steps of the wizard:** not built yet (`_on_sections_accepted` only logs; see its TODO).

### SAP2000 connection decisions (`core/sap_client.py`)

* Uses `pythonnet` with the .NET Framework runtime (`pythonnet.load("netfx")`) and loads `SAP2000v1.dll` directly, like `NET.addAssembly` in the MATLAB code.
* **Only SAP2000 v23 is supported** (company rule: everyone has it). The DLL is bundled in `src/core/vendor/sap2000_v23/SAP2000v1.dll`, so the install path and signature differences between versions do not matter. After connecting, the running SAP version is checked and anything other than v23 gives a clear error. SAP2000 itself must still be installed.
* The DLL is small, so it ships inside the app update package; running it from `%LocalAppData%` is not a problem (confirmed by the user). `build.py` zips every file under `src/`, not only `.py`, so the DLL is included; `.gitignore` must not exclude it.
* `openSapModel.m` also deletes non-`.sdb` files in the model folder; this was **deliberately not ported**.
* The SAP2000 imports are lazy, so the app starts even if `pythonnet` is missing.

## SLD to SAP (current state)

Converts the piping SLD (CSV files written by `SLD2SAP.lsp` from the AutoCAD layer `TAGGED_LOADS`) into two SAP2000 import tables: joints (point loads, circles) and distributed frame loads (rectangles). It is a port of the user's working MATLAB tool `SLD2SAP.m` (v1.4). The full algorithm, file formats, token table, error codes and the verified differences from MATLAB are in `docs/sld_to_sap_algorithm.md`; this section only describes the code.

* **Inputs** (`ui/page.py`): `z0` (m, default 0), tolerance (mm, default 10), end tolerance (mm, default 5), EQ.Z coefficient (**default 1**, also the default of `SldParams.eqz_coef`), friction coefficient (default 0.15); a list of CSV files or folders; the SAP2000 Excel export (sheets `Connectivity - Frame` and `Joint Coordinates`). The output folder is asked in a dialog when **Convert** is pressed (the dialog starts next to the Excel file); existing output files with the same names are overwritten without asking. `LISP` is not changed.
* **Downloads on the page:** "Download LISP" saves `assets/SLD2SAP.lsp`; "Open Rules" opens `assets/Rules of SLD2SAP.pdf` from a copy in the temp folder (so a PDF viewer never locks a file inside the app folder and blocks updates).
* **All problems are shown together, automatically.** Any change of an input (file added or removed, Excel file, any parameter) re-runs the whole check in a background worker (debounced 350 ms; older results are dropped by a version counter; the loading overlay appears only if it takes longer than a moment). Without a valid Excel file only the structure check (`check_structure`, CSV files only, S codes) runs; with it, `convert` also adds the matching errors (M codes). The Excel file is read once and cached by (path, modification time, size). Nothing stops at the first error.
* **All or nothing:** `Convert` is enabled only when the full check has no error, and `write_outputs` refuses to write when the result has errors. Warnings (W01: two points with the same coordinates) do not block. Convert runs `convert` again (the Excel comes from the cache) before writing.
* **Issue table:** sorted by file, then errors before warnings, then `Index`. Double-clicking a row copies its CAD coordinates (mm) to find the object in AutoCAD.
* **Outputs:** `SAP2000 Joint Coordinates.xlsx` (sheet `Joint Coordinates`) and `SAP2000 Distributed Loads.xlsx` (sheet `Frame Loads - Distributed`), written from row 4 into the workbooks in `templates/`. Headers are fixed SAP strings and must not be changed. `relDist` / `absDist` are not rounded (bit-for-bit comparison with MATLAB is the goal). Frame names are written as numbers only when they are a canonical integer string (`9`, not `007`), else as text.
* **Behaviours that differ from MATLAB on purpose** (all confirmed in the guide): the "load inside the frame" test is correct for reversed frames (`lo = min(pI,pJ)`, `hi = max(pI,pJ)`), `endTolerance` is applied at the beam ends and the distances are clamped to `[0, Length]`, point names must be unique over all files (S10), `LS`/`LT` duplicates are checked in plans, a non-numeric value after `=` (S14) and a text that is only a number (S15) are errors, halves are rounded away from zero (`round_mm`), point names are compared case-insensitively (SAP is not case sensitive), a negative load value is an error (S18), `V=`/`FV=` twice in one rectangle is S11, a non-numeric `Index` is S17, a CSV with no data rows is S01, a frame with a non-positive `Length` is M06 and a joint with non-numeric coordinates is M07. When the Connectivity file is unusable (M03/M04) no frame matching runs, so there is no flood of M01. `check_structure` takes `z0` so W01 in stage 1 uses the user's value (`ui/page.py` passes `self.params.z0`).
* **Not implemented:** warning W02 (file name does not match the origin row), plan rectangles that are not axis-aligned (never produced by the current LISP), graphical preview (declined), direct import into SAP2000 through OAPI (later phase).

## Rules

* The shell (`src/ui/`) never contains plugin-specific logic; a plugin never controls the shell. Plugin UI lives in `plugins/<name>/ui/`, business logic in `plugins/<name>/services/`. Code shared by several plugins (like the SAP connection) lives in `src/core/`.
* Do not remove or rename `main()` and `ping_app()` without updating the launcher contract (`ping_app()` is the post-update self-check; it must work without a display). Changes to `docs/contract.md` or `launcher.py` break installed copies and need a new Setup.
* The version number lives in `src/version.py` only (plus `pyproject.toml`, checked by `build.py`). Do not type it anywhere else.
* Create planned files (e.g. further Auto Design `services/` modules) only when they are actually implemented. Every package folder needs an `__init__.py`, otherwise `pyproject.toml` (`packages.find include = ["src*"]`) skips it.
* Always use the project runtime; `python` / `py` may not exist globally.
* Tests of a plugin live in `tests/<plugin name>/`.
* After changing any code, state which file changed and its exact folder location (project instruction).
